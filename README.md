# baluard-org

The Baluard website: homepage, security white paper, and the apt/dnf package
repository, served by GitHub Pages at https://baluard.app (and
https://baluard-org.github.io until the custom domain resolves).

## Layout

- `index.html` — the homepage. Hand-written, no build step, no JavaScript.
- `security.html` — the security white paper, rendered from the markdown in
  the main repository.
- `repo/` — the apt and dnf package repository, generated by
  `just repo-stage` in the main repository. Committed on purpose: GitHub
  Pages serves from git, so the packages must live in this history.
- `CNAME` — the custom domain GitHub Pages serves.

## Release flow

From a checkout of `baluard-org/baluard` after `just release-sign dist`:

```sh
just repo-stage dist ../baluard-org/repo
cd ../baluard-org
python3 tools/render.py path/to/baluard/docs/security-white-paper.md security.html
git add -A && git commit -m "release 0.1.0" && git push
```

`render.py` regenerates the white paper page from the current markdown.
Update the download links in `index.html` to the new version tag in the same
commit.

## Notes

- `.nojekyll` keeps GitHub Pages serving the tree as-is.
- Each release adds ~17 MB of package binaries to this repository's history.
  Fine for years under GitHub's limits; if it ever matters, drop old versions
  from `repo/` in the same release commit.
