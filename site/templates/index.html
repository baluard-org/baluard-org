Zero-Server Architecture

Why the architecture is the security model.

Most password managers store everyone's vaults in one giant cloud database. If that company gets breached or sold, your encrypted passwords and unencrypted metadata end up in new hands. Baluard works like a personal safe in your home: your passwords stay on your own hardware, so there is no central database to break into.

LAYER 1 / WHERE YOUR DATA LIVES

A Safe in Your Home

Your vault stays on your physical phone and computer, encrypted with a key only you hold. Every entry is padded to identical size so observers cannot guess what is inside.

AES-256-GCM • Argon2id • Size-Padded
LAYER 2 / HOW DEVICES CONNECT

Keys Exchanged in Person

Your phone and computer pair directly with each other like two people swapping keys face-to-face. No central account, no corporate sign-in, and no company server in the middle.

Ed25519 Device Keys • Local IPC Tokens
LAYER 3 / HOW VAULTS SYNC

Sync Through Your Own Notebook

Sync your vault through a private Git repo, your home server, or a USB drive. The remote host sees only scrambled ciphertext. Even a total breach of the sync host exposes zero passwords.

Git-Native Transport • Signed Commits
Sovereign Capabilities

Engineered for sovereignty and longevity.

Built for autonomy, durability, and device-level custody.

Hardware Key Vault Sealing

Enroll a YubiKey or FIDO2 hardware token to seal the entire vault. Even if an adversary extracts your master password, the vault refuses to decrypt without a physical touch on your security key.

  • Hardware challenge-response via FIDO2 hmac-secret
  • Canary verification validates authentication state without exposing master keys

All 9 Cipher Types + Passkeys

Store logins (with embedded passkeys), cards, identities, SSH keys, bank accounts, driver licenses, passports, secure notes, and code signing keys.

  • RFC 6238 compliant integrated TOTP code generator
  • Native SSH and code signing key storage with public key export

Spaces & Family Collaboration

Share specific credential collections with family or team members without a central identity provider. Uses cryptographic invite codes and device-to-device grants.

  • Phrase-only emergency recovery kit for estate and family continuity
  • Role-based access grants: Owner, Admin, Editor, and Viewer

Browser Extension & Autofill

Native browser integration for Firefox, Chrome, and Chromium-based browsers. Autofill credentials, capture new logins, and sign into WebAuthn passkeys directly through local daemon IPC.

  • Direct local socket communication with zero cloud telemetry or analytics
  • Instant domain matching and one-click TOTP code filling

Git 3-Way Merge Conflict Resolution

Because Baluard is built on Git, concurrent edits on two offline devices never overwrite each other. When divergent changes occur, Baluard lets you inspect and resolve discrepancies field-by-field.

  • Preserves divergent offline edits without silent overwrites
  • Full commit history preservation for audit and rollback

Prefer system updates via APT or DNF? (Ubuntu, Debian, Fedora) View repository instructions ↓

Install from the official repository to pull beta updates directly through your system package manager.

Ubuntu / Debian (APT):
sudo curl -fsSL -o /usr/share/keyrings/baluard-archive-keyring.asc https://baluard.app/repo/baluard-release.asc && curl -fsSL https://baluard.app/repo/baluard.sources | sudo tee /etc/apt/sources.list.d/baluard.sources && sudo apt update && sudo apt install baluard

Uses the deb822 format (default on Ubuntu 24.04+ and Debian 13+). The armored key is used directly, no dearmor step.

Fedora (DNF):
sudo dnf config-manager addrepo --from-repofile=https://baluard.app/repo/baluard.repo && sudo dnf install baluard

Fedora 41+ (dnf 5). On RHEL and clones (dnf 4): sudo dnf config-manager --add-repo=https://baluard.app/repo/baluard.repo

Repository signing key fingerprint: 223310EA BF1A B6FE E6BD DF3E 2A53 1D54 E6D7 4804. Always verify this fingerprint before trusting repository imports.
